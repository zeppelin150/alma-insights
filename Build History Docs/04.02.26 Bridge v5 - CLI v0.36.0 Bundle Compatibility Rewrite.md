Our bridge (`gemini_bridge.mjs`) imported these deleted paths directly. Bridge died with exit code 1 on boot. All NLP scans failed.

## Architecture: 4-Tier Self-Healing Boot

```
Bridge boot
  |
  +-- Tier 1: FAST PATH (checksum match)
  |     Read CLI package.json version + hash gemini.js import block
  |     If matches cached fingerprint -> use cached config adapter -> boot in ~1.5s
  |
  +-- Tier 2: AUTO-UPDATE (checksum mismatch)
  |     Re-extract loadCliConfig from gemini.js via brace-counting parser
  |     Diff against cached copy
  |     Run export probe (typeof checks on chunk exports)
  |     Run smoke test (loadSettings -> Config -> getGeminiClient)
  |     If pass -> update cache -> boot in ~2s
  |
  +-- Tier 3: LLM SELF-REPAIR (extraction fails)
  |     Send diff + error to Claude API (native fetch, independent of bridge)
  |     Fallback: old subprocess gemini CLI
  |     Validate generated adapter with same smoke test
  |     If pass -> update cache -> boot in ~10-30s (first time only)
  |
  +-- Tier 4: USER ALERT (LLM fix fails validation)
        Emit bridge_fatal with clear message
        Log diff summary for developer diagnosis
```

### Chunk Resolution Flow

```
gemini.js (entry point)
  |
  | import { loadSettings, initializeApp, ... } from "./chunk-UNM3DGTG.js"
  | import { Scheduler, Config, GeminiClient, ... } from "./chunk-QVTX2M5J.js"
  | import { ... } from "./chunk-S2IQOR7T.js"
  |
  v
chunk_resolver.mjs
  |
  | 1. Read gemini.js as text
  | 2. Regex: /import \{([^}]+)\} from "\.\/([^"]+\.js)"/gs
  | 3. findChunkFor('loadSettings')     -> chunk-UNM3DGTG.js (CLI chunk)
  | 4. findChunkFor('getOauthClient')   -> chunk-QVTX2M5J.js (Core chunk)
  | 5. findChunkFor('loadServerHierarchicalMemory') -> chunk-S2IQOR7T.js (Helper chunk)
  |
  v
Dynamic import() from resolved chunk paths
  |
  v
exportProbe() validates all required symbols exist
```

## All Fixes (8 total)

### Fix 1: Dynamic Chunk Resolution (boot crash)

**Problem**: `globalRequire.resolve('@google/gemini-cli/dist/index.js')` -> MODULE_NOT_FOUND -> exit code 1

**Fix**: New `chunk_resolver.mjs` parses `gemini.js` import statements at runtime to discover chunk filenames. Chunks have content hashes that change every CLI release (e.g., `chunk-UNM3DGTG.js`), so they can't be hardcoded.

**Files**: `src/gemini/chunk_resolver.mjs` (162 lines, NEW)

### Fix 2: Config Adapter (loadCliConfig unavailable)

**Problem**: `loadCliConfig`, `parseArguments`, `validateNonInteractiveAuth` are private functions inside `gemini.js` (which auto-runs `main()` on import, so we can't import it).

**Fix**: Bridge-adapted copy of `loadCliConfig` (~385 lines from the CLI bundle) with simplified replacements:
- `parseArguments` (250 lines of yargs) replaced with 20-line `buildBridgeArgv()`
- `validateNonInteractiveAuth` replaced with 15-line `validateBridgeAuth()`
- All dependencies verified as exported from chunks (zero private deps remain)

**Files**: `src/gemini/config_adapter.mjs` (567 lines, NEW)

### Fix 3: Scheduler Constructor Change

**Problem**: v0.36.0 changed Scheduler from `new Scheduler({ config, messageBus, ... })` to `new Scheduler({ context: { config, messageBus }, ... })`. First streaming call crashed.

**Fix**: Updated constructor call in `callGeminiStreaming()`:
```js
// BEFORE:
const scheduler = new Scheduler({ config, messageBus: config.getMessageBus(), ... });

// AFTER:
const scheduler = new Scheduler({
  context: { config, messageBus: config.getMessageBus() },
  messageBus: config.getMessageBus(), ...
});
```

**Files**: `src/gemini/gemini_bridge.mjs` (line 408)

### Fix 4: Model Router Bypass

**Problem**: `PREVIEW_GEMINI_MODEL_AUTO` = `"auto-gemini-3"` triggers a remote NumericalClassifier that adds 1-18 seconds latency per API call. Canary probes showed P50=18s instead of ~1-3s.

**Fix**: Default model set to `DEFAULT_GEMINI_FLASH_MODEL` (`"gemini-2.5-flash"`) instead of auto-routing alias. Also disabled `modelSteering`, `dynamicModelConfiguration`, and `gemmaModelRouter` in Config.

**Files**: `src/gemini/config_adapter.mjs` (model resolution section)

### Fix 5: Native Tool Registration

**Problem**: CLI v0.36.0 models use native Gemini function calling instead of our fenced `tool_call` code blocks. The Scheduler tries `config.getToolRegistry().getTool("store_classification")` -> undefined -> crash.

**Investigation**: The tool registered in `allKnownTools` Map but `getTool()` returned undefined because `isActiveTool()` checked the exclude list, and `getExcludeTools()` excluded all unrecognized tools.

**Fix**:
1. Created `StoreClassificationTool` extending `BaseDeclarativeTool` with proper schema
2. Created `StoreClassificationInvocation` extending `BaseToolInvocation` with no-op `execute()`
3. Patched `config.getExcludeTools()` to remove `store_classification` from the exclude set
4. Introspection probe verifies registration after boot

**Files**: `src/gemini/bridge_tools.mjs` (179 lines, NEW)

### Fix 6: New GeminiEventType Handlers

**Problem**: CLI v0.36.0 added 11 new event types. Unhandled events caused crashes or silent data loss. `Thought` events contained `{subject, description}` objects (not text) which contaminated `full_text` with `[object Object]`.

**Fix**: Added handlers for all new event types in the streaming loop:
- `Thought` -> ignored (not text content)
- `Finished` -> let loop end naturally
- `InvalidStream` -> classified as recoverable error
- `Retry` -> reset stall timer
- `ModelInfo`, `Citation`, `ChatCompressed`, `ContextWindowWillOverflow`, `ToolCallResponse`, `ToolCallConfirmation`, `UserCancelled` -> logged and ignored
- Unknown future events -> catch-all handler (log + continue)

**Files**: `src/gemini/gemini_bridge.mjs` (streaming loop, lines ~558-620)

### Fix 7: Batching Race Condition

**Problem**: "Provider payout rate dissatisfaction" TRC had 47 tickets but only 37 were batched (24+13). 10 tickets silently dropped.

**Root cause**: `_get_tickets_for_batch()` has an exclude clause that removes already-classified tickets (`AND ticket_id NOT IN (SELECT ... WHERE scan_id = ?)`). For multi-chunk TRC batches, this shrinks the ticket pool between chunks. Then chunk slicing (`chunk_size = ceil(remaining / chunk_total)`) uses the original `chunk_total` on the reduced pool, causing positional math to skip tickets.

**Fix**: Exclude clause only activates for single-chunk batches (`chunk_total <= 1`). Multi-chunk batches keep the full ticket pool for correct boundary math.

```python
# BEFORE:
if scan_id:
    exclude_clause = " AND ticket_id NOT IN (...)"

# AFTER:
if scan_id and chunk_total <= 1:
    exclude_clause = " AND ticket_id NOT IN (...)"
```

**Files**: `src/agents/scan_orchestrator.py` (line 1933)

### Fix 8: Error Diagnostic Chain

**Problem**: `unknown` errors in retry log showed no diagnostic info. Bridge death events showed generic "watchdog detected exit" with no exit code or error context.

**Fix**:
- Worker forwards `message` and `raw` fields from bridge result to batch result
- Orchestrator includes `message` and `raw` in retry event metadata
- Bridge death events show exit code + last stderr line
- Stderr ring buffer (5 lines) captures last output before process death
- CLI version logged on each bridge boot

**Files**: `src/agents/worker_agent.py`, `src/agents/scan_orchestrator.py`, `src/agents/gemini_bridge_wrapper.py`
